# 问题导航栏（ChatGPT / Claude）

版本：1.2.0（2026-11-25）

这是一个 Edge / Chrome 浏览器扩展，在 **ChatGPT** 和 **Claude** 网页右侧，把当前对话里你提过的每个问题显示成一条短横线：

- 鼠标悬停在横线上，可以预览对应的问题。
- 点击横线，会跳到对应问题。
- 你正在阅读的位置会高亮成一条更长、颜色更深的横线。

整个扩展完全在本地运行：不联网、不读取 Cookie 或登录令牌、不收集任何数据，也没有第三方库。

## 一、安装

### Edge

1. 下载本仓库：在 GitHub 页面点 **Code → Download ZIP** 后解压，或者用 `git clone`。把文件夹放在一个**不会被删除**的位置。
2. 在地址栏打开 `edge://extensions/`，打开左侧的 **"开发人员模式"**。
3. 点击 **"加载解压缩的扩展"**，选择那个文件夹。注意要选里面直接有 `manifest.json` 的那一层。
4. 点工具栏的拼图图标，把 **"问题导航栏"** 固定到工具栏。
5. **刷新**已经打开的 ChatGPT 或 Claude 页面。

### Chrome

步骤和 Edge 相同，只是地址改为 `chrome://extensions/`，按钮名称是"开发者模式"和"加载已解压的扩展程序"。

### 注意事项

- 安装后不要删除或移动那个文件夹，否则扩展会失效。
- 装好以后会自动运行，不需要每次手动启动。
- 扩展支持 Chromium 111 及以上版本，目前的 Edge 和 Chrome 都满足。

### 从旧版本升级

用新文件覆盖原文件夹，然后在扩展页点本扩展卡片上的 **"重新加载"**，再刷新 ChatGPT 或 Claude 页面。

## 二、首次验证

1. 打开一个问题比较多的对话，右侧应该出现一列短横线。
2. 悬停横线，应该显示"第 N / 总数 个问题"和问题内容。
3. 点击横线，页面应该跳到那个问题，问题周围会短暂闪一下绿色边框。
4. 手动滚动页面，较长的高亮横线应该跟着移动。
5. 发一个新问题，几秒内横线应该多出一条。
6. 点击工具栏里的扩展图标，弹窗应该显示 **"正常运行"**，"网站"一项显示 ChatGPT 或 Claude，"完整列表读取"显示 **"可用"**。

## 三、使用说明

| 操作 | 效果 |
|---|---|
| 悬停短横线 | 预览问题，最多显示 6 行 |
| 点击短横线 | 跳到这个问题并短暂高亮；问题还没渲染出来时也能跳过去 |
| 点击导航栏顶部的三个小点 `···` | 让网页加载更早的一批消息，然后跳到最早的问题 |
| 扩展弹窗 → 启用导航栏 | 打开或关闭导航栏，设置会被记住 |
| 扩展弹窗 → 重新扫描 | 重新识别当前对话 |
| 扩展弹窗 → 加载完整历史 | 一次把所有更早的消息加载完，然后回到原来的位置 |

**关于长对话**

ChatGPT 和 Claude 都用了两种机制来处理长对话：

- **虚拟列表**：只渲染屏幕附近的几条消息，其他消息不在页面里。
- **分批加载**：打开对话时只加载最近的一批消息，滚到最上面时才加载更早的。

扩展的应对方式：

- 直接读取网页已经放在内存里的对话列表，所以**已加载的问题会全部显示**，还没渲染出来的也能点击跳转。
- 只要可能还有更早的消息，导航栏顶部就会出现 `···` 标记。
  - Claude 会准确告诉我们"还有没有更早的消息"，所以这个标记很准。
  - ChatGPT 只能告诉我们"可能还有"，所以有时要多点一次，扩展才能确认已经到开头。
- 加载更早消息这一步由网页自己完成，扩展只是把页面滚到顶部来触发它。**扩展本身不发任何网络请求。**

**什么时候显示**

- 对话里至少有 2 个问题时才显示。
- 导航栏放在聊天区域的右边缘。如果正文右侧没有足够的空隙，会自动隐藏，避免遮挡文字，例如窗口太窄，或者打开了 Claude 的 Artifact 面板。空间恢复后会自动重新出现。
- 跳转过程中，如果你自己转动滚轮、按键或触摸屏幕，跳转会立即停止，不和你抢滚动。

## 四、安全与隐私

- 只在 `chatgpt.com`、`chat.openai.com` 和 `claude.ai` 上运行。
- **只申请了 `storage` 权限**，用来保存"启用"和"调试"两个开关。
- **不发起任何网络请求。** 代码里没有 `fetch`、`XMLHttpRequest`、`WebSocket` 或远程脚本，扩展页面的安全策略还设置了 `connect-src 'none'`，从规则上禁止联网。
- **不读取账号令牌、Cookie，也不读取 localStorage 或 sessionStorage。**
- 聊天内容**不保存、不上传**，只放在当前标签页的内存里，用来显示导航栏，刷新页面后就清空。
- 弹窗里的"复制诊断信息"只包含计数和页面结构信息，**不包含任何聊天文字**。

为了支持虚拟列表，扩展做了下面几件事，这里如实说明：

1. **`bridge.js` 运行在网页环境中**，只读地读取网页已经放在内存里的对话列表，包括问题文字（最多 400 字）、编号、位置，以及是否还有更早的消息。只有当扩展发出请求时，它才会把结果通过页面内部的事件交给扩展。
2. **在 Claude 上跳转时，`bridge.js` 会调用 Claude 页面自带的 `scrollToIndex` 函数。** Claude 自己的"对话内查找"功能也用这个函数。它只负责滚动页面，不修改任何数据。调用前还会核对行号和消息 ID 是否一致。
3. **在 ChatGPT 上跳转时，扩展会滚动聊天区域**，并在滚动前发送一个"滚轮"事件，告诉 ChatGPT 这是用户主动滚动，否则 ChatGPT 会把页面拉回底部。这个事件本身不会让页面滚动，也不会触发任何其他操作。

代码文件说明：

| 文件 | 作用 |
|---|---|
| `manifest.json` | 扩展配置和权限 |
| `bridge.js` | 网页环境里的数据桥 |
| `content.js` | 导航栏的主体逻辑 |
| `popup.*` | 工具栏弹窗 |
| `icons/` | 图标 |

## 五、故障排查

先点工具栏的扩展图标，看弹窗显示什么：

| 弹窗显示 | 原因 | 解决方法 |
|---|---|---|
| 当前标签页不是 ChatGPT / Claude，或页面需要刷新 | 页面是在安装或更新扩展之前打开的 | 刷新页面 |
| 已关闭 | 导航栏开关被关掉了 | 勾选"启用导航栏" |
| 导航栏未显示，原因是"问题少于 2 个" | 对话太短 | 正常现象 |
| 导航栏未显示，原因是"正文右侧空间不足" | 窗口太窄，或打开了侧边面板 | 拉宽窗口或关闭面板 |
| 完整列表读取"不可用"，但导航栏能显示 | 网站改版，页面数据的结构变了。扩展已自动改用"只识别页面上已渲染的问题"的方式 | 能继续用，但长对话里只会显示滚动经过的问题 |
| **未识别到消息（网站页面结构可能已变化）** | 页面上的识别规则全部失效 | 见第六节 |

对话页右侧如果出现**橙色小圆点**，表示停留 6 秒仍未识别到任何消息，处理方法同上表。

如果想看详细日志：在弹窗"高级"里勾选"调试日志"，然后按 F12 打开控制台，用 `问题导航栏` 过滤。

## 六、网站改版后的维护（2026-11-25 实测结构）

### ChatGPT

| 标记 | 含义 |
|---|---|
| `.thread-scroll-container` | 聊天滚动区域 |
| `[data-chatgpt-conversation-selection-target="对话ID"]` | 对话内容区。切换对话后，旧对话会隐藏保留在页面里，所以识别时要按对话 ID 选择 |
| `[data-virtualized-turn]` | 虚拟列表里每个回合的外层 |
| `[data-content-search-turn-key]` | 回合编号 |
| `[data-user-message-bubble="true"]` | 用户消息气泡 |

页面数据：

- 虚拟列表组件里的 `rows[i].turn.items` 中，`type` 为 `user-message` 的那一项的 `message` 字段是问题文字。
- `topOffsetsPx` 是每个回合的位置。
- `pagination.cursor` 不为空，表示可能还有更早的消息。

### Claude

| 标记 | 含义 |
|---|---|
| `[data-testid="transcript-list"]` | 消息列表；离它最近、可以滚动的上层元素就是滚动区域 |
| `[data-testid="user-message"]` | 用户消息 |
| `[data-turn-key="消息ID"]` | 消息外层，带有消息 ID |
| `[role="article"][aria-posinset][aria-setsize]` | 消息在已加载消息中的序号 |
| `<html data-mode="light\|dark">` | 深浅色 |

页面数据：

- 消息列表组件的 `rows` 里有 `messageUuids`、`messageChainData` 和 `hasEarlier`。
- `messageChainData[i].lastMessage` 的 `sender` 为 `human` 时就是用户问题，文字在 `content[].text`。
- 跳转用的是页面子组件里带 `scrollToIndex` 和 `items` 的那个组件，`scrollToIndex(i, {align:'start'})` 就是"跳到第 i 行"。

### 修改方法

- 页面识别失效：在 `content.js` 的 `STRATEGIES` 最前面加一条新规则。
- 页面数据读取失效：修改 `bridge.js` 里的 `collectChatGPT` 或 `collectClaude`。
- 改完后在扩展页点"重新加载"，再刷新网页。

可以调整的参数在 `content.js` 开头：

- `MIN_ITEMS_TO_SHOW`：至少多少个问题才显示导航栏。
- `RAIL_WIDTH` / `RAIL_RIGHT_GAP`：导航栏的宽度和位置。
- 样式在 `CSS_TEXT` 里。
