# ChatGPT 问题导航栏（Edge / Chrome 扩展）使用说明

版本：1.1.0（2026-11-25）

这个扩展会在 ChatGPT 网页右侧，把当前对话里你提过的每个问题显示成一条短横线：

- 鼠标悬停在横线上，可以预览对应的问题。
- 点击横线，会跳到对应问题。
- 你正在阅读的位置会高亮成一条更长、颜色更深的横线。

## 一、安装

### Edge

1. 解压 `chatgpt-question-nav-v1.1.0.zip`，得到 `chatgpt-question-nav` 文件夹。把它放到一个**不会被删除**的位置，例如 `D:\Extensions\chatgpt-question-nav`。
2. 在地址栏打开 `edge://extensions/`，打开左侧的 **"开发人员模式"**。
3. 点击 **"加载解压缩的扩展"**，选择那个文件夹。注意要选里面直接有 `manifest.json` 的那一层。
4. 点工具栏的拼图图标，把 **"ChatGPT 问题导航栏"** 固定到工具栏。
5. **刷新**已经打开的 ChatGPT 页面。

### Chrome

步骤和 Edge 相同，只是地址改为 `chrome://extensions/`，按钮名称是"开发者模式"和"加载已解压的扩展程序"。

### 注意事项

- 安装后**不要删除或移动**那个文件夹，否则扩展会失效。
- 装好以后会自动运行，不需要每次手动启动。
- 浏览器偶尔会提示"关闭开发人员模式扩展"，选择保留即可。
- 扩展支持 Chromium 111 及以上版本，目前的 Edge 和 Chrome 都满足。

## 二、首次验证

1. 打开一个问题比较多的 ChatGPT 对话，右侧应该出现一列短横线。
2. 悬停在横线上，应该显示"第 N / 总数 个问题"和问题内容。
3. 点击横线，页面应该跳到那个问题，问题周围会短暂闪一下绿色边框。
4. 手动滚动页面，较长的高亮横线应该跟着移动。
5. 发一个新问题，几秒内横线应该多出一条。
6. 在 ChatGPT 设置里切换到深色主题，横线应该变成浅色。
7. 点击工具栏里的扩展图标，弹窗应该显示 **"正常运行"**，并且"完整列表读取"一项显示 **"可用"**。

## 三、使用说明

| 操作 | 效果 |
|---|---|
| 悬停短横线 | 预览问题，最多显示 6 行 |
| 点击短横线 | 跳到这个问题并短暂高亮；问题还没渲染出来时也能跳过去 |
| 点击导航栏顶部的三个小点 `···` | 让 ChatGPT 加载更早的一批消息，然后跳到最早的问题 |
| 扩展弹窗 → 启用导航栏 | 打开或关闭导航栏，设置会被记住 |
| 扩展弹窗 → 重新扫描 | 重新识别当前对话 |
| 扩展弹窗 → 加载完整历史 | 一次把所有更早的消息加载完，然后回到原来的位置 |

**关于长对话**

新版 ChatGPT 有两个机制会影响长对话：

- **虚拟列表**：页面同时只渲染屏幕附近的几个回合，其他回合不在页面里。扩展直接读取 ChatGPT 已经放在页面内存里的对话列表，所以**已加载的问题会全部显示在导航栏上**，没渲染出来的也能点击跳转。
- **分批加载**：打开一个长对话时，ChatGPT 只加载最近一批回合（实测每批 5 到 10 个）。更早的回合要等你滚到最上面才会加载。页面不会告诉我们总共有多少个回合，所以：
  - 只要可能还有更早的消息，导航栏顶部就会出现 `···` 标记，点一下加载一批。
  - 点击"加载完整历史"，会一直加载到对话开头。
  - 加载更早消息这一步是 ChatGPT 页面自己完成的，扩展只是把页面滚到顶部来触发加载。**扩展本身不发任何网络请求。**

**显示规则**

- 对话里至少有 2 个问题时才显示导航栏。
- 聊天区域窄于 700px 时自动隐藏，避免遮挡正文。
- 跳转过程中，如果你自己转动滚轮、按键或触摸屏幕，跳转会立即停止，不和你抢滚动。

## 四、安全与隐私

- **只在** `chatgpt.com` 和 `chat.openai.com` 上运行。
- **只申请了 `storage` 权限**，用来保存"启用"和"调试"两个开关。没有申请访问其他网站、标签页、Cookie、下载或网络的权限。
- **不发起任何网络请求。** 代码里没有 `fetch`、`XMLHttpRequest`、`WebSocket` 或远程脚本，扩展页面的安全策略还设置了 `connect-src 'none'`，从规则上禁止联网。
- **不读取账号令牌、Cookie，也不读取 localStorage 或 sessionStorage。**
- 聊天内容**不保存、不上传**，只放在当前标签页的内存里，用来显示导航栏，刷新页面后就清空。
- 弹窗里的"复制诊断信息"只包含计数和页面结构信息，**不包含任何聊天文字**。
- 全部是原生 JavaScript 和 CSS，没有任何第三方库。

为了支持新版界面，扩展做了下面三件事，这里如实说明：

1. **`bridge.js` 运行在页面环境中**，用来读取 ChatGPT 已经放在内存里的对话列表数据，包括每个回合的编号、问题文字（最多 400 字）、位置，以及是否还有更早的消息。
   - 它**只读**，不修改页面数据，也不调用 ChatGPT 的任何函数。
   - 只有当扩展发出请求时，它才会通过页面内部的事件把结果交给扩展。
   - 这些问题文字本来就显示在你自己的页面上。
2. **跳转时会滚动聊天区域。** 滚动前，扩展会向聊天区域发送一个"滚轮"事件，告诉 ChatGPT 这是用户主动滚动。
   - 原因是：ChatGPT 有一个"自动跟随到底部"的状态，只有检测到用户主动滚动才会解除，否则会把页面拉回底部。
   - 这个事件本身不会让页面滚动，也不会触发任何其他操作。
3. **加载更早的消息时，扩展只是把页面滚到顶部**，由 ChatGPT 自己去加载。

代码文件说明：

| 文件 | 作用 |
|---|---|
| `manifest.json` | 扩展配置和权限 |
| `bridge.js` | 页面环境里的只读数据桥 |
| `content.js` | 导航栏的主体逻辑 |
| `popup.*` | 工具栏弹窗 |
| `icons/` | 图标 |

## 五、故障排查

先点工具栏的扩展图标，看弹窗显示什么：

| 弹窗显示 | 原因 | 解决方法 |
|---|---|---|
| 当前标签页不是 ChatGPT，或页面需要刷新 | 页面是在安装或更新扩展之前打开的 | 刷新 ChatGPT 页面 |
| 已关闭 | 导航栏开关被关掉了 | 勾选"启用导航栏" |
| 导航栏未显示，原因是"问题少于 2 个" | 对话太短 | 正常现象 |
| 导航栏未显示，原因是"聊天区域过窄" | 窗口太窄，或者打开了画布或侧栏 | 拉宽窗口 |
| 完整列表读取"不可用"，但导航栏能显示 | ChatGPT 改版，页面数据的结构变了。扩展已自动改用"只识别页面上已渲染的问题"的方式 | 能继续用，但长对话里只会显示滚动经过的问题。把诊断信息发给维护者 |
| **未识别到消息（ChatGPT 页面结构可能已变化）** | 页面上的识别规则全部失效 | 见第六节 |
| 运行中，但出现过错误 | 脚本运行时出过异常 | 复制诊断信息发给维护者 |

对话页右侧如果出现**橙色小圆点**，表示停留 6 秒仍未识别到任何消息，处理方法同上表。

其他情况：

- **点击后没有准确停在问题上**：如果你在跳转过程中滚动了页面，跳转会主动停止。再点一次即可。
- **想看详细日志**：在弹窗"高级"里勾选"调试日志"，然后按 F12 打开控制台，用 `ChatGPT问题导航` 过滤。启动时一定会输出 `v1.1.0 已启动`；如果没有这一行，说明扩展没有注入，请检查扩展是否启用，并刷新页面。

## 六、ChatGPT 改版后的维护

**识别问题**（`content.js` 里的 `STRATEGIES`）按顺序尝试，命中哪条就用哪条。弹窗里的"识别规则"一项会显示当前用的是哪条：

1. 页面列表数据：来自 `bridge.js`，能拿到包括未渲染问题在内的完整列表。
2. `[data-user-message-bubble="true"]`：新版界面的用户消息气泡，2026 年 11 月实测有效。
3. `[data-message-author-role="user"]`：旧版界面。
4. `[data-turn="user"]`
5. `conversation-turn` 加"You said"标题。

**新版界面的关键标记**（2026-11-25 实测）：

| 标记 | 含义 |
|---|---|
| `.thread-scroll-container` | 聊天滚动区域 |
| `[data-chatgpt-conversation-selection-target="对话ID"]` | 对话内容区。切换对话后，旧对话会被隐藏但保留在页面里，所以识别时必须按对话 ID 选择 |
| `[data-virtualized-turn]` | 虚拟列表里每个回合的外层 |
| `[data-content-search-turn-key="回合ID"]` | 回合编号，和页面数据里的 `row.id` 一致 |
| `[data-user-message-bubble="true"]` | 用户消息气泡 |

页面数据：`bridge.js` 从虚拟列表元素的 React 节点往上查找，读取：

- 组件的 `rows`：每个回合的 `turn.items` 里，`type` 为 `user-message` 的那一项的 `message` 字段，就是问题文字。
- `topOffsetsPx`：每个回合的位置。
- 分页信息 `pagination.cursor`：不为空表示还有更早的消息。注意 `pagination.numTurns` 只是每批加载的数量，**不是总数**。

**改版后如何修：**

1. 页面识别失效：按 F12，用元素选择器点一下你自己的提问，找一个能唯一标记"用户消息"的属性，加到 `STRATEGIES` 的最前面。
2. 页面数据读取失效：导航栏仍然可以用，只是长对话体验会变差。需要按上面的结构重新定位数据，修改 `bridge.js`。
3. 改完后在 `edge://extensions/` 点本扩展的"重新加载"，再刷新 ChatGPT 页面。

**可以调整的参数**（在 `content.js` 开头）：

- `MIN_ITEMS_TO_SHOW`：至少多少个问题才显示导航栏，默认 2。
- `MIN_CONTAINER_WIDTH`：聊天区域窄于多少像素就隐藏，默认 700。
- 样式在 `CSS_TEXT` 里。

**更新扩展**：用新文件覆盖原文件夹，然后在扩展页点"重新加载"，再刷新 ChatGPT 页面。

**卸载扩展**：在扩展页点"删除"，然后删掉对应的文件夹。
